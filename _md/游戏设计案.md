## 1. 概述

### 1.1 一句话定位

一款基于整数网格、**纯逻辑零运气**的 3D 推箱解谜游戏。以**章节递进**的方式逐步引入机制：从经典推箱，到彩色按钮开门，到多角色切换协同，再到带层高与坡度的立体推箱。

### 1.2 核心体验

> "我只能推，不能拉；所以每一步都要先想清楚后三步。"

玩家面对的是一个**不可逆**的世界。乐趣不来自操作，而来自**前瞻规划、死锁识别与子问题分解**。

### 1.3 目标用户

喜欢纯逻辑解谜、空间推理、规划类玩法的玩家（推箱子、Baba Is You、Cosmic Express、Sokoban 社区用户）。

---

## 2. 设计支柱（Design Pillars）

1. **纯逻辑，零运气，零反应**
   无时间压力、无随机数、无操作精度要求。失败只能归因于思考不足。
2. **不可逆性带来重量**
   "只能推不能拉"是难度根源。撤销与重开必须廉价，但决策本身要有分量。
3. **机制逐章递进**
   每一章只引入一个新变量，先教学后组合，保证难度曲线平滑。
4. **机制可插拔**
   所有关卡元素（按钮、颜色、坡度等）必须能由关卡编辑器无代码扩充。

## 4. 世界与网格定义

### 4.1 网格化世界

- 世界由**整数网格**构成，所有可交互对象严格吸附在格子上。
- 主平面为 **XZ 平面**，Y 轴表示**高度（层）**。
- 单格边长（cellSize）：默认 `1.0` 世界单位。
- 格坐标：`(x, y, z)`；第一至三章只在同一站立层活动，第四章启用层间移动。

### 4.2 柱体模型（地板与墙统一）

整个世界是**高度场**：每个 `(x, z)` 是一根从 y=0 往上堆的实心柱。

- **地板和墙是同一种物体**，区别只是柱高：矮柱是地板，高柱是墙。
- 角色占据某个体素，站立条件：**该体素为空，且正下方是实体**。
- 地形数据存**柱顶那一格**：`柱高 = pos.y + 1`，角色站在柱顶 `y = 柱高`。
- 高度差：**只能往下**（掉落），往上要靠坡度（第四章）。

### 4.2.1 站立面（顶面）

每格的**可站立顶面 T** = 地形柱高 + 该格现存可解锁墙高 + 该格箱子 1。

- 角色脚下 = 所在格的顶面。
- **箱子和可解锁墙都会把所在格"加高"**：箱子顶 = 支撑面 + 1，墙顶 = 支撑面 + 墙高。
- 移动判定只看**顶面高度**（见 §5.3），不单独区分"地板 / 箱顶 / 墙顶"。

### 4.3 隐含底面 / 虚空 / 材质

- **隐含底面**：没单独写地形的格子，默认按 `baseHeight` 生成（0 = 虚空）；`baseMaterial` 决定其外观。新建关卡默认 `baseHeight = 1`。
- **虚空**：出界的格子、以及 `baseHeight = 0` 时没有地形的格子，是**无限高的绝对空气墙**（不可进入 / 穿越 / 掉落）；也可用显式 `void` 把某格从底面抠成洞。
- 所以**掉落不会掉进虚空**（虚空是墙不是坑）：邻格是虚空时，往那个方向走一律被挡住。
- **材质**：地形 `type` 只是外观（浅灰 / 深灰 / 黑…），**不影响逻辑**，逻辑只看高度。

### 4.4 3D 表现原则

- 逻辑是网格数据，**表现是 3D**：地板、墙、箱子、角色、坡均为 3D 模型。
- 逻辑位置与表现位置解耦：逻辑瞬变，表现为插值动画。
- 相机：半俯视，跟随当前操控角色，支持旋转/缩放（见 §9）。

## 5. 移动规则（通用）

### 5.1 移动模型：纯格步进

- 角色每次移动**跨越恰好一个格子**。
- 按一次走一格；持续按住则固定间隔**连续步进**。
- 表现插值（建议 `0.12s` / 格），但**逻辑在按键瞬间结算**。
- 禁止自由移动 / 惯性 / 加减速，保证谜题确定性。

### 5.2 推箱三原则（经典规则，全程有效）

1. **只能推，不能拉**
2. **一次只能推一个箱子**（箱子后方必须是空且可进入的格）
3. **推的前提**：目标格可进入，且箱子后方格可进入且无占据物

> FAQ：经典推箱子**不能**一次推动两个箱子。箱子后方若有箱、墙、角色，推动一律失败。

### 5.3 移动结算（顶面高度判定）

设脚下高度为 `y`，邻格**可站立顶面**为 `T`（见 §4.2.1）：

| 条件 | 结果 |
|---|---|
| `T == y` | **走上去**（含踩上箱子顶 / 墙顶），角色停在 `y` |
| `T < y` 且 `T > 0` | **掉下去**：xz 进一格，落到 `T` |
| `T > y`，且该格箱子底面 == `y` | **推箱**：箱子先动一格，角色进入原箱格 |
| 其余（虚空 / 更高且非可推箱） | 拒绝，角色不动 |

- **不能往上爬**：顶面比脚下高、又不是可推的箱子，一律挡住。
- **掉落是单向的**：没有坡度就回不到高处（`§9.3` 的自动寻路因此只走"可原路返回"的路径）。
- **箱子被推下台阶也会掉**：箱子推/落到的落点 = 该格的支撑面（地形 + 现存墙）。

### 5.4 死锁（Deadlock）

死锁 = 箱子进入**永远无法再被推动**且不在抵达点上的状态。

本作中死锁**不属于规则禁止项**，而是玩家需自行识别的风险，系统仅提供**软提示**：

- **静态死格**：预计算的、推入必死的格子（墙角、贴墙非目标格）
- **动态死锁**：2×2 箱子方阵、相互冻结的箱子组
- 表现：箱子/格子变灰提示，不弹窗、不禁操作

> 设计意图：保留自主性与"我早该看出来"的顿悟感。

## 6. 机制系统

### 6.1 机制三要素

```
触发器 Trigger  --连线-->  动作 Action  --作用于-->  目标 Target
（如：按钮被按下）        （如：解锁）              （如：某颜色可解锁墙）
```

### 6.2 第二章：彩色按钮 + 彩色可解锁墙

| 项 | 规则 |
|---|---|
| 按钮颜色 | 颜色编号 `1~6`（红 / 蓝 / 黄 / 绿 / 紫 / 橙） |
| 触发方式 | 被**箱子或角色**占据，且**与按钮同层**时按下 |
| 作用目标 | 同颜色的「可解锁墙」 |
| 作用效果 | 按钮**被压住**期间，同色墙消失；**松开的那一帧恢复** |
| 墙顶站立 | 墙顶与脚下齐平时**可以走上去**（墙顶算可站立面） |
| 墙消失时 | 站在墙上的人 / 箱**掉下去**；掉进去后**仍占据该格**，墙不会在其头顶第一时间重现 |

设计要点：
- **持按**是第二章的核心：想让箱子 / 角色穿过门，必须有东西**一直压住按钮**；或者用"箱子自己压着按钮、再把它顶进门里"（自推法）——因为门只有在箱子离开按钮那一瞬才会关，而此时箱子已经在门格上占住了。
- 同一颜色可有多个按钮、多块墙（"一处触发、多处开路"）。
- 颜色匹配由编辑器配置，不写死在代码里。

> **已定稿**：改为**持按**机制（不再是永久解锁）。离开按钮后同色墙恢复，除非墙格被箱 / 角色占住。

### 6.3 第三章：多角色切换

| 项 | 规则 |
|---|---|
| 出生点 | 关卡含 **m 个出生点**（本章 m = 2 或 3），生成 m 个玩家 |
| 操控 | 同一时刻只有一个玩家响应 WASD |
| 切换 | `Tab` 循环切换当前操控角色 |
| 切换成本 | **不消耗步数、不消耗时间**，任意时刻可用 |
| 人物实体性 | 角色是**实体**，占据格子，**不可被穿过、不可被推动** |
| 阻塞 | 角色若不主动撤离，会像墙一样**造成堵塞**（箱子推不动、其他角色过不去） |
| 相机 | 跟随当前激活角色 |

设计要点：
- 双角色形成"一个角色牺牲自己开路 / 保持站位，另一个通过"的经典结构。
- 角色实体性既是资源也是障碍：站位本身是一种可消耗/可回收的"工具"。
- 切换零成本，鼓励自由推演。

> **待确认**：角色之间能否踩在对方头上？（暂定：**不能**，角色是不可堆叠实体，仅第四章起箱子可被踩。）

### 6.4 机制求解（设计约束）

- 机制在**每次世界状态变化后**重新求解，直至稳定（链式联动一次算清）。
- 必须保证：**结果只依赖当前世界状态，不依赖求解顺序**，避免歧义。
- 出现无解震荡（A 开 B、B 关 A）视为**关卡设计错误**，由编辑器校验拦截。

## 7. 第四章：层高、坡度与重力

### 7.1 层与行走（体素模型）

- 世界为**体素网格**，每格层高**理论上无上限**（可堆叠任意层）。
- 角色占据一个体素 `(x, y, z)`；站立条件：该体素为空，且**正下方为实体块**。
- 一次移动的判定只看**当前高度**：目标格在**当前层无阻碍**即可进入（有实体块则该方向被阻挡，即表现为墙）。
- 高度差通过**坡度**跨越（见 §7.2）；没有坡度就无法上到更高层。

### 7.2 坡度（统一几何规则）

- **所有坡都是 1/2 正方体**（楔形），占用一格，并带一个**攀爬方向**（4 方向之一，编辑器可旋转）。
- 本质接近**"带方向的可攀爬墙"**：**没有滑动**，站上去稳定，也**不会自动前进到下一格**。
- 进入坡格的规则：

| 进入方向 | 结果 |
|---|---|
| 沿**攀爬方向**进入 | **上坡**：站上该坡格本身，高度 **+1**（停在坡格，不越格） |
| 其余 **3 个方向**进入 | 坡度箱 → 视作**常规箱子**推动；坡度墙 → 视作**固定障碍**，不可进入 |

- 例：坡位于 `(x+1, z)`、攀爬方向 `+x`。玩家从 `(x, z)` 向 `+x` 走 → 落在坡格 `(x+1, y+1)`，**不会再前进到 `(x+2)`**。
- 由于只站到坡格本身，**坡后方是否虚空 / 是否为更高的围墙均不影响上坡**——紧邻虚空的坡同样可以攀爬。
- 从坡格继续移动时，按常规规则（含重力）判定目标格。

### 7.3 坡度墙 vs 坡度箱

- **坡度墙**：固定地形，不可推动；3 个非上升面均视为墙。
- **坡度箱**：可推动物体，朝向固定；**攀爬方向面不可推**（进入即上坡），其余 **3 面按常规箱子推动**。
- 二者共用同一套几何与上坡规则，仅"是否可推"不同。

### 7.4 重力（同一步内结算）

- 重力**在一步内结算**：一次输入 = 一次完整结算 = **一个可撤销的步**。
- 结算顺序：

```
移动判定（当前层是否有阻碍）
  └ 可进入 → 到达目标体素
       └ 检查下方是否踩实
            ├ 踩实   → 结束
            └ 未踩实 → 下落，直到落到支撑面（或停在阻挡物之上）
```

- 角色与箱子遵循**同一套重力**。
- 箱子被从上层推下 / 推上坡时，同样掉落。

### 7.5 重量与堆叠

- **可推动重量上限 = 1**。
- 单个箱子（重量 1）可推。
- **箱子叠箱子**、**箱子上站人** → 重量 ≥ 2 → **不可推动**。
- 箱子**允许堆叠**（可垒高作为平台）。
- **不可推动承载自己的箱子**（脚下方）。
- 结论：不存在"站在箱子上把箱子推走"的情况，规则上天然禁止。

### 7.6 虚空

- 虚空是**绝对空气墙**：不可进入、不可穿越、不可从中掉落。
- 虚空的坡**仍可攀爬**（坡只把人抬到坡格本身，不依赖坡后方有落脚点）。

### 7.7 第四章交互补充

- 箱子成为**可垫高的可踩平台**，堆叠用于抵达高处。
- 推动、站立、下落的**顺序依赖**是第四章主要难度来源。
- 多层结构（二层、三层乃至更高）用于构建上下联动的解谜空间。

## 8. 关卡元素总表（可扩充）

所有元素遵循 **分类（Category）+ 类型（Type）** 两级结构，类型 ID 使用**字符串**以便无痛扩充。

### 8.1 地形 = 材质 × 高度

"地板 / 墙"不再作为独立类型，而是**材质（外观）× 高度（逻辑）**的组合：

| 概念 | 说明 |
|---|---|
| 虚空 | 无柱（或显式 `void`），无限高绝对墙 |
| 地板 | 矮柱（如高 1） |
| 墙 | 高柱（比相邻高） |
| 材质 | 浅灰 / 深灰 / 黑 /（可扩充） |

### 8.2 机关

| 类型 | 引入章 | 说明 |
|---|---|---|
| 箱子 | 1 | 可推动 |
| 抵达点 | 1 | 箱子目标 |
| 出生点 | 1 | 角色初始位置（带玩家编号） |
| 彩色按钮 | 2 | 被**同高度**的人 / 箱占据时触发 |
| 可解锁墙 | 2 | 按钮被压时**消失**、松开**恢复**；**墙顶可站立**，消失时其上的人/箱坠落 |
| 坡度墙 / 坡度箱 | 4 | 上坡 +1 层（**下落**已在 M3.5 实现） |

> 新增元素：**只需新增类型定义 `.asset`，不改动框架代码**。详见《关卡编辑器设计案》。

## 9. 操作与相机

### 9.1 键位（默认，可配置）

| 操作 | 键位 |
|---|---|
| 移动 | `W` `A` `S` `D`（相机相对） |
| 点击寻路 | 鼠标左键 |
| 切换角色 | `Tab`（第三章起） |
| 撤销一步 | `R` |
| 重置本关 | `P` |
| 相机旋转 | `Q` / `E`（或鼠标右键拖动） |
| 相机缩放 | 鼠标滚轮 |
| 暂停/菜单 | `Esc` |

### 9.2 方向输入与相机对齐（正交四方向）

- 世界移动恒为 **4 个正交方向**（`+x` / `-x` / `+z` / `-z`），**不存在斜向移动**。
- **默认视角**：俯角 **60°**，看向 `+z`。此时 `+z` 为"正方向"：
  - `W → +z`，`S → -z`，`D → +x`，`A → -x`
- **相机旋转中（按住 `Q` / `E`）**：**禁止 WASD 输入**。
- **松开的一瞬间**：视角固定，从 `+x / -x / +z / -z` 中选出**与当前视角朝向最接近**的一个，作为新的"正方向"。
  - `W` → 正方向
  - `S` → 反方向
  - `D` → 正方向顺时针 90°
  - `A` → 正方向逆时针 90°
- 方向对齐是**离散吸附（四选一）**，保证输入永远映射到 4 个正交方向之一。

### 9.3 点击寻路（自动行走）

- **鼠标左键点击场景中的可站立面**（即实体块顶面 = 地板），选中目标格。
- 系统在网格上搜索路径，控制**当前激活角色**自动逐格走过去。
- **自动行走期间不可推箱子**：路径必须绕开所有箱子 / 障碍格。
  - 若**不存在**"不推箱也能到达"的路径 → 本次点击**不移动**（可给提示）。
- **只走"可原路返回"的路径**：寻路只使用**可双向通行**的边。
  - 下落是单向的（掉下去爬不回来），所以**需要掉下去才到的目标，点击后无反应**。
  - 目的：避免误触把角色送到回不来的低处。
- 自动行走中按任意移动键或再次点击 → **立即取消**。
- 路径搜索：网格 BFS（四方向，保证最短）；箱子、墙、其他角色（第三章）均视为障碍。

### 9.4 撤销与重置（核心辅助）

- **逐步撤销（`R`）**：每按一次回退**一步**，可连续回退到关卡初始状态。
- **重置本关（`P`）**：一键回到关卡初始状态。
- 二者必须**免费且即时**，是游戏的基本盘，不是附加功能。

### 9.5 相机

- 半俯视，**默认俯角 60°，看向 `+z`**。
- 自动跟随当前激活角色，平滑插值。
- 支持手动旋转（`Q` / `E`）与缩放，便于观察第四章多层结构。
- 旋转结束后按 §9.2 重新确立正方向。
- 切换角色时相机平滑过渡，不瞬移。

## 10. 反馈与表现

- **移动表现**：角色 / 箱子移动插值（0.12s / 格）；逻辑瞬时、表现平滑。
- **可推行提示**：角色面向的可推箱子轻微高亮。
- **死锁提示**：进入死格的箱子变灰（软提示）。
- **按钮反馈**：按下时按钮及同色墙同步高亮，解锁瞬间有明显的通路面变化。
- **抵达反馈**：箱子推上抵达点时有明确视觉 / 音效确认。
- **重力反馈**：下落有轻微加速与落地反馈。
- 音效与特效：移动、推箱、抵达、解锁、下落各一套（占位待补）。

## 11. 关卡目标与通关条件

### 11.1 通关条件

- **基础条件**：所有「抵达点」都被「箱子」覆盖。
- **箱子数 ≥ 抵达点数**即可（多余的箱子可当垫子 / 压钮）；箱子数**少于**抵达点数 = 非法，由编辑器校验拦截。

### 11.2 可选附加条件（后续扩展）

- 指定角色必须到达指定标记点
- 限制最大步数 / 推数（挑战模式）
- 按钮必须保持激活状态通关

### 11.3 章节关卡编制规范

| 章 | 出生点 | 箱子/抵达点 | 机制约束 |
|---|---|---|---|
| 第一章 | 1 | n : n | 纯推箱，无机制 |
| 第二章 | 1 | n : n | 出现彩色按钮与同色可解锁墙，必须可解且不依赖顺序歧义 |
| 第三章 | 2 或 3 | n : n | 角色实体阻塞；可利用角色站位作为解法的一部分 |
| 第四章 | 1~3 | n : n（含坡度箱） | 层高 / 坡度 / 重力，注意落点与支撑 |

### 11.4 评价体系（后续）

- 三星制：以步数 / 推数相对最优解的比值划分（最优解由离线求解器提供）。

### 12.1 难度代理指标

| 指标 | 难度关系 |
|---|---|
| 箱子数量 | ↑ 难 |

| 角色数量 / 协同需求 | ↑ 难（第三章） |
| 层数与坡度数量 | ↑ 难（第四章） |

### 12.2 难度曲线原则

- 新机制先出**单一变量教学关**，再出组合关。
- 严禁难度断崖：新机制引入后至少 2 关用于巩固。
- 单关元素数量递增。

## 15. 与编辑器 / 技术接口约定

（技术策划视角，保证设计与工具自洽）

- 关卡**唯一数据源**为 JSON，由《关卡编辑器》产出，运行时只读取。
- 世界 = **柱体高度场**：`terrain` 存柱顶（`柱高 = pos.y + 1`）；`baseHeight / baseMaterial` 表示隐含底面；显式 `void` 表示挖洞。
- 每个对象都是「类型 ID + 格坐标 + 参数」；类型定义由**类型注册表**（`.asset`）统一管理。
- 机关（物件 / 标记）在同一格只能放一个；`player` 记出生点的玩家编号。
- 彩色按钮与墙的对应、机制连线，全部**可视化配置**，不写死在代码。
- 新增元素 / 机制：**只新增类型定义与机制实现，不改工具与框架核心**。
- 详细数据结构与扩充机制见《关卡编辑器设计案》。

## 附 A：经典推箱子规则 FAQ

| 问题 | 答案 |
|---|---|
| 能一次推两个箱子吗？ | **不能**。箱子后方必须是空地，连推属于魔改规则。 |
| 能把箱子从墙上拉回来吗？ | **不能**。只有推，没有拉。 |
| 箱子推进墙角还有救吗？ | 没有，属于永久死锁，只能撤销。 |
| 角色能推动箱子到自己脚下吗？ | 不能，角色不能与箱子同格。 |

## 附 B：术语表

| 术语 | 含义 |
|---|---|
| 格 / Cell | 世界的最小逻辑单位 |
| 纯格步进 | 每次移动恰好跨越一格，逻辑瞬时结算 |
| 死锁 Deadlock | 箱子进入永久无法推动且非目标的状态 |
| 静态死格 Dead Square | 预计算的、推进去必死的格子 |
| 层高 / 高度场 | 第四章中每格堆叠的实体块数量 |
| 坡度墙 | 固定斜面地形，可上 1 层 |
| 坡度箱 | 可推动斜面物体，受重力 |
| 机制连线 Link | 触发器 → 动作 → 目标 的关联关系 |
| 类型注册表 | 集中管理所有关卡元素定义的资产 |
