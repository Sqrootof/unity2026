---

## 0. 这个工具是干什么的

让策划在一个可视化界面里，用鼠标画出关卡，存成 JSON 文件，并在保存前自动查错、评估可解性。

它**不做**的事：

- 不做"游戏里的编辑器"（玩家看不到它）
- 不管玩法逻辑（它不知道什么叫"推箱子"）
- 不改动 Unity 本身

---

## 1. 它在项目里以什么形式存在

它就是一堆文件，放在 `Assets/` 里，和普通脚本一样进 Git。区别在于**编译位置**：

| 脚本放哪 | 代码包 | 进游戏包吗 |
|---|---|---|
| `Assets/_Project/Framework/Runtime/` | 运行时包 | ✅ |
| `Assets/_Project/Framework/Editor/` | 编辑器专用包 | ❌ |

编辑器脚本用到 `UnityEditor`（面板、绘制、撤销），该命名空间在打包后的游戏里不存在，所以必须分开。

## 2. 关卡数据（当前模型）

一个关卡是**四张清单** + 一个**隐含底面**：

```json
{
  "id": "1-1",
  "name": "第一步",
  "schemaVersion": 1,
  "size": { "x": 5, "y": 2, "z": 5 },

  "baseHeight": 1,
  "baseMaterial": "gray_light",

  "terrain": [
    { "type": "gray_dark", "pos": { "x": 0, "y": 1, "z": 0 } }
  ],
  "objects": [
    { "type": "box", "pos": { "x": 2, "y": 1, "z": 2 } }
  ],
  "markers": [
    { "type": "spawn",  "pos": { "x": 2, "y": 1, "z": 1 }, "player": 0 },
    { "type": "target", "pos": { "x": 2, "y": 1, "z": 3 } }
  ],
  "links": []
}
```

### 2.1 柱体模型（核心）

- 每个 `(x, z)` 是一根**从 y=0 往上堆的实心柱**。
- `terrain` 里存的是**柱顶那一格**：`柱高 = pos.y + 1`；角色站在柱顶 `y = 柱高`。
- **"地板"和"墙"是同一种物体**，区别只是柱高：矮柱就是地板，高柱就是墙。
- `terrain` 的 `type` 是**材质**（外观），不影响逻辑，逻辑只看高度差。

### 2.2 隐含底面

- `baseHeight`：没有单独写地形的格子，默认按这个高度生成（`0` = 虚空）。
- `baseMaterial`：隐含底面的材质。
- 新建关卡默认 `baseHeight = 1`、浅灰 → 整片可直接走的地板，只需再放机关/墙。

### 2.3 虚空

- **虚空 = 绝对空气墙，无限高**：不可进入、不可穿越、不可掉落。
- 出界的格子、以及 `baseHeight = 0` 时没有地形的格子，都是虚空。
- 也可以在 `terrain` 里写一条 `type = "void"` 的显式虚空，把某格从底面抠掉（挖洞）。

### 2.4 机关

- "物件"和"标记"在编辑层面**统一叫机关**，同一格**只能放一个**。
- 内部按 `storeKind` 存到两张表：`object`（可推动，如箱子）/ `marker`（静态，如抵达点、出生点）。
- `markers` 里出生点用 `player` 字段记玩家编号；按钮 / 可解锁墙用 `color`（`"1"`~`"6"`）与 `height`（墙高）。
- **默认类型**：地形 `gray_light / gray_dark / black`；机关 `spawn / box / target / unlock_wall / button`。
- **保存时 `id` 自动同步为文件名**（去掉 `.json`）。

### 2.5 连线

- `links` 存"触发器 → 动作 → 目标"，目前为空，第二/四章（按钮等）使用。

## 3. 类型注册表

每种可放的东西都是一个 `.asset`（`TileTypeDefinition`），字段：

| 字段 | 含义 |
|---|---|
| `id` | 唯一名字（字符串，如 `gray_light`、`box`） |
| `displayName` | 界面中文名 |
| `category` | `terrain` / `mechanism` |
| `storeKind` | 机关才用：`object` / `marker` |
| `color` | 占位颜色（材质外观 / 机关颜色） |
| `placeholderHeight` | 机关占位高度（格子的比例） |
| `prefab` / `surfaceMaterial` | 正式外观（可留空，用占位） |
| `blocking` | 是否阻挡（占位用，逻辑以高度为准） |
| `sortOrder` | 排序 |

**扩充方式**：新建一个 `.asset`，工具界面自动出现对应按钮/材质，不用改代码。

## 4. 界面

```
┌───────────── 工具栏 ─────────────┐
│ 文件▾  编辑▾           关卡名 *  │
├──────────────────────────────────┤
│ 类型注册表 [ ]                   │
│ 游玩视角  俯视视角               │
│ 关卡列表 / 关卡信息 / 调色板      │
│ 校验结果                         │
└──────────────────────────────────┘
（内容可上下滚动）
```

### 4.1 文件菜单（文件 ▾）

- **新建...** → 弹窗输入 `长(X)` / `宽(Z)`，确定后生成一片高度 1 的浅灰底面
- **打开 → (关卡名)** → 直接选关卡打开（下拉列表，不是文件管理器）
- **保存 / 另存...**
- 有未保存改动时，打开/新建会先弹 `保存 / 不保存 / 取消`

### 4.2 编辑菜单（编辑 ▾）

- **撤销 / 重做**（关卡自己的撤销栈；无历史时置灰）
- **校验** → 手动跑一遍，结果打到 Console
- **裁切外围虚空格** → 逐边检查，整条全虚空就裁掉并整体平移坐标、缩小长宽（可撤销）

### 4.3 关卡列表

- **未选取关卡时**在窗口中列出 `Assets/_Project/Content/Levels` 下的所有 json，点击打开
- 选取后改用「文件 → 打开」下拉切换

### 4.4 调色板

- 分类 Tab：`地形(Terrain)` / `机关(Mechanism)`
- **地形**：笔刷 `[块] [底面]` + **柱高** `[1][2][3]+输入` + **材质**色块（浅灰/深灰/黑）
- **机关**：类型按钮（出生点 / 箱子 / 抵达点 / 可解锁墙 / 按钮，固定顺序）+ **颜色**下拉（按钮 / 可解锁墙，`颜色1`~`颜色6`）+ **墙高**（可解锁墙）

### 4.5 关卡信息

- 关卡 ID、`长(X)` / `宽(Z)`（可改，缩小会清理越界数据）
- `底面高度`、`底面材质`
- 地形 / 机关 数量统计

## 5. 怎么操作

**鼠标（场景视图内）**

| 操作 | 效果 |
|---|---|
| 左键 | 按当前模式放置/擦除 |
| 右键 | 留给 Unity 转视角（不占用） |

**工具栏**

| 操作 | 效果 |
|---|---|
| 放置 / 擦除 / 矩形 / 吸管 | 工具模式（在地形/机关 Tab 上方） |
| 矩形 | 按住左键拖出矩形，松开批量填充（一次撤销） |
| 吸管 | 点一格，取它的机关 / 材质 + 柱高为当前画笔；机关还会一并取**颜色 / 墙高** |
| 游玩视角 / 俯视视角 | 摆正场景相机 |

**快捷键**

| 操作 | 效果 |
|---|---|
| `Ctrl+S` | 保存关卡 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |

### 5.1 放置 / 擦除规则

- **块笔刷**：把该格设成指定材质 + 柱高（覆盖原地形）
- **底面笔刷**：把该格还原成隐含底面（删掉显式地形）
- **机关**：放到该格柱顶；每格仅一个（会清掉该格原有机关）
- **擦除（地形分类）**：地形没了 → 上面的机关失去支撑一起消失；有底面时该格变成洞（显式虚空）
- **擦除（机关分类）**：只擦机关，不动地形
- **无实际变化的操作不会记录撤销、不置脏**（例如用底面刷子刷已是底面的格子）
- **改柱高 / 改底面高度后**，自动把所有机关 / 物件的 `pos.y` 刷新到所在柱高（`ResyncHeights`），避免 JSON 里留下过期的高度

### 5.2 撤销 / 重做

- 每关一套**本地撤销栈**（保存前后的快照），与 Unity 全局撤销无关
- 打开/新建关卡时清空历史
- `*` 表示"当前内容 ≠ 上次保存内容"；撤销回保存态会自动去掉 `*`

### 5.3 场景显示

- 地形：加粗线框柱（0.9 宽）
- 隐含底面：柱 + **底部一个叉**（与显式块区分）
- 虚空：0 高度处**红色方框 + 叉**
- 机关：线框四棱锥
- 问题格：错误红框 / 警告黄框
- 鼠标悬停：加粗框（放置黄 / 擦除橙）

## 6. 校验器 + 可解性检测

### 6.1 结构校验（窗口底部列出，可点击定位）

| 级别 | 检查 |
|---|---|
| ❌ 错误 | **箱子数 < 抵达点数**；没有出生点；机关悬空；机关/地形越界；同格多个地形 |
| ⚠️ 警告 | 出生点玩家编号重复；没有抵达点 |

> 箱子数 **≥** 抵达点数即合法（多余箱子可作垫子 / 压钮）。

- 保存时若有错误 → 弹「有 N 个错误，仍要保存吗？」
- 错误格在场景里标红框、警告标黄框，点条目相机飞过去

### 6.2 可解性检测

- 结构校验通过后，出现 **「检测是否有解」** 按钮
- 用 BFS 求解器找解，显示：`有解：最少 N 步 / N 推`、`无解（已穷尽搜索）`、`未知（搜索量超限）`
- 求解器与运行时同一套模型：**持按按钮 / 可解锁墙显隐 / 顶面站立 / 下落 / 推箱下台阶**
- 推箱子是 PSPACE-完全，复杂关卡会触顶返回"未知"，属正常

## 7. 层高相关（部分实现）
